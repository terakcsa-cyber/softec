# Руководство пользователя Vuln Intel Platform

Полное руководство для аналитика уязвимостей, инженера ИБ и оператора SOC. Описывает ежедневную работу в веб-интерфейсе без доступа к серверу.

**Аудитория:** пользователи с учётной записью (JWT). Часть действий (дайджест, DLQ) доступна только администраторам — см. [ADMIN_GUIDE.md](./ADMIN_GUIDE.md).

## 1. Первый вход и безопасность

### Первичная настройка (пустая база)

Если в системе ещё нет пользователей, при открытии `/login` появится форма **первичной настройки**:

1. Укажите **email** администратора.
2. Задайте **пароль** (минимум 12 символов).
3. Повторите пароль.

После создания первого пользователя эта форма **больше не отображается**. Повторно «сбросить» систему через UI нельзя — только через администратора БД.

### Обычный вход

1. Откройте URL платформы (например `https://vuln-intel.example.com`).
2. Введите email и пароль.
3. Если включена **двухфакторная аутентификация (TOTP)**, введите код из приложения (Google Authenticator и т.п.).

Сессия ограничена по времени (access token ~15 минут); при истечении обновите страницу или войдите снова. При массовых **401** в интерфейсе — сессия истекла: перелогиньтесь.

### Рекомендации пользователю

- Не передавайте учётные данные коллегам — заведите отдельные аккаунты (если администратор включил регистрацию).
- Используйте TOTP для учётных записей с правами администратора.
- Не копируйте JWT-токены из DevTools в чаты.

## 2. Обзор интерфейса

Платформа построена как **единый дашборд** с модулями (вкладками/панелями):

| Модуль | Назначение |
|--------|------------|
| **Обзор** | Сводные метрики, графики, быстрые ссылки |
| **CVE** | Поиск и карточки уязвимостей |
| **Срочные 24ч** | Hot CVE с KEV / высоким EPSS / CVSS≥9 |
| **Threat** | Лента exploit-сигналов, дайджест |
| **Задачи** | Кампании по вендору/продукту |
| **ФСТЭК** | Бюллетени и BDU |
| **Patch** | RSS бюллетеней вендоров |
| **VOC** | Кейсы, смены, watchlist |
| **Настройки** | Секции: Интеграции · Пользователи · Внешний вид · Безопасность · Веб / TLS · Обновления |

Навигация между модулями сохраняет контекст в URL — можно делиться ссылкой на конкретный CVE или задачу (внутри организации).

### Настройки (кратко)

| Секция | Кто | Что |
|--------|-----|-----|
| **Интеграции** | admin | Telegram, LLM/TEXT_ENGINE, VulnCheck, MaxPatrol |
| **Пользователи** | admin | Создание/роли/`enabled`/сброс пароля |
| **Веб / TLS** | admin | Домен: LE или self-signed. **IP без DNS:** самоподписанный с SAN IP (основной путь; предупреждение браузера). Опционально LE IP shortlived (~6 дн.) при certbot≥5.4 и :80 |
| **Обновления** | admin | Проверка git SHA и apply (если включён update-helper) |
| Внешний вид / Безопасность | пользователь | Тема, смена пароля, TOTP |

## 3. Дашборд и сводка

### Что показывает сводка

- **Общее число CVE** в каталоге.
- **CVE за последние 24 часа** (по дате публикации NVD).
- **KEV** — записи в каталоге CISA Known Exploited Vulnerabilities.
- **EPSS** — покрытие таблицей вероятностей эксплуатации.
- **Risk scores** — сколько CVE имеют рассчитанный unified risk score.

Цифра **risk_score count** — это **всего записей в БД за всё время**, а не «очередь» или «застывший счётчик». Актуальность пересчёта смотрите по свежим CVE в ленте и по `computed_at` в карточке (косвенно — через актуальный score).

### Вендоры и продукты

Блок агрегирует CVE по вендорам/продуктам из NVD CPE. Используйте для фокуса на своём стеке.

## 4. Работа с CVE

### Поиск

1. Откройте модуль CVE или используйте глобальный поиск.
2. Поддерживаются:
   - идентификатор `CVE-2024-12345`;
   - фрагмент описания;
   - вендор / продукт.

Фильтры: период публикации, сортировка по релевантности или дате.

### Карточка CVE

Карточка открывается **на весь экран** с вкладками:

| Вкладка | Содержание |
|---------|------------|
| **Общая** | Описание, метрики, risk score, LLM-обогащение, сигналы |
| **Уязвимые продукты** | CPE / vendor-product пары |
| **Исправления** | Ссылки на патчи, advisory |
| **Источники** | NVD raw, внешние ссылки |

### Risk score и Perimeter score

- **Risk score** — агрегированная оценка 0–100 (CVSS, EPSS, KEV, exploit intel, упоминания).
- **Perimeter score** — эвристика «насколько это бьёт по периметру» с учётом сетевого контекста.

Обе метрики **объяснимы**: в UI показываются факторы (factors), из чего сложился балл.

### LLM-обогащение (ИИ)

Для **свежих CVE (≤24ч)** обогащение запускается **автоматически** в фоне (если настроен LLM).

Для **старых CVE**:
- нажмите **Обогатить** в карточке (если администратор не отключил `ALLOW_MANUAL_ENRICH`);
- или дождитесь digest prepare для CVE в суточном отчёте.

Статусы обогащения:
- успешный JSON с summary/recommendations;
- `LLM not configured` — endpoint не настроен;
- `_enrich_error` — временный сбой (повторится sweep).

**Не паникуйте**, если enrich в очереди: для hot CVE sweep повторяет попытки раз в час (idempotency bucket).

### Связь с задачами

Из карточки CVE можно:
- **создать новую задачу** (кампанию по вендору);
- **добавить CVE в существующую задачу**.

Счётчик открытых задач отображается на карточке.

## 5. Срочные CVE за 24 часа

Блок **«Срочные CVE за последние 24 часа»** — укороченный список для немедленного внимания.

### Категории фильтра

| Категория | Критерий |
|-----------|----------|
| **Срочные** | Все hot в окне 24ч с сильным сигналом |
| **KEV** | CVE в каталоге CISA KEV |
| **CVSS ≥ 9** | Критический base score |
| **EPSS ≥ 50%** | Высокая вероятность эксплуатации по EPSS |

Карточки **раскрашены** по доминирующему сигналу (KEV > EPSS > CVSS).

### Действия

- Клик по карточке → полная карточка CVE.
- Создание VOC-кейса / задачи — через контекстные кнопки (если доступны в вашей сборке).

## 6. Threat Intelligence (лента угроз)

Модуль **Threat** показывает **exploit-сигналы** за выбранное окно (по умолчанию несколько дней).

### Колонки и фильтры (бакеты)

- **Тип сигнала / бакеты**: PoC, public exploit, VulnCheck KEV, EPSS spike, Telegram mentions и др.
- **Сортировка**: по threat score или по времени.
- **Вендоры**: мультивыбор.
- **Только новые** за окно.
- **Watchlist**: только CVE из вашего списка наблюдения.

### Threat score

Композитный балл на основе сигналов exploit intel, KEV, EPSS, risk score. Используйте для приоритизации в ленте.

### Обновление данных (Threat Intel Refresh)

Кнопка обновления запускает синхронизацию VulnCheck + пересчёт exploit intel. Есть **cooldown** (~2 мин), чтобы не перегружать API.

## 7. Суточный Threat Digest и Telegram

**Threat Digest** — суточный отчёт: текст в Telegram + PDF с fact sheets по hot CVE.

### Кто может отправлять

Отправка и подготовка дайджеста требуют прав **администратора** (`ADMIN_EMAILS` в конфигурации). Обычный пользователь видит ленту Threat, но не кнопку отправки дайджеста (получит 403).

### Настройка Telegram (один раз)

Администратор в **Настройки → Интеграции**:
1. Включить Telegram.
2. Указать **bot token** (от @BotFather).
3. Указать **chat id** канала/чата.

### Процесс отправки (важно)

Кнопка **«Дайджест в Telegram»** выполняет **три фазы**:

```
1. Prepare  →  2. Poll status  →  3. Send
```

1. **Prepare** — API ставит в очередь LLM-обогащение для CVE, попадающих в PDF (до `hotLimit`, по умолчанию 20). Показывается прогресс `done/total`.
2. **Poll** — UI опрашивает статус каждые ~1.5 сек (до 8 минут).
3. **Send** — только если `completed=true`. Иначе показывается ошибка и **PDF не уходит**.

Это защищает от отправки «пустого» дайджеста без LLM-текста.

### Если prepare не успел за 8 минут

- LLM медленный (Ollama на GPU) или очередь `ai.enrich` большая.
- **Действия:** подождать завершения enrich в фоне, повторить кнопку позже; или попросить админа проверить очередь и LLM health.

## 8. Задачник по уязвимостям (Vuln Tasks)

Задачник для **кампаний по обработке уязвимостей** (1–2 ответственных, малые команды).

### Создание задачи

1. Укажите **вендор** (обязательно) и опционально **продукт**.
2. Заголовок генерируется автоматически или вводится вручную.
3. Задача создаётся в статусе **Новая**.

### Статусы

| Статус | Смысл |
|--------|-------|
| **Новая** | Только завели, не взяли в работу |
| **В работе** | Анализ / согласование / патчинг |
| **Закрыта** | Решение принято, evidence заполнено |

Перетаскивание на **доске (Kanban)** меняет статус.

### CVE в задаче

- Добавление через поиск (минимум 3 символа).
- Одна задача — **много CVE**.
- Один CVE — в **нескольких** задачах.

### Поля закрытия

Для перевода в закрытый статус заполните:
- **review date** — дата пересмотра;
- **decision** — решение;
- **evidence** — доказательства (тикеты, скриншоты, ссылки).

### Task Score

Сервер считает **агрегированный score** задачи по всем CVE (risk, KEV, EPSS) с модификатором статуса. Используйте для сортировки списка.

### Audit trail

Вкладка **История** — кто и когда менял поля (audit_log).

## 9. ФСТЭК / БДУ

### Лента бюллетеней

Парсинг публичной ленты ФСТЭК (по умолчанию Telegram `t.me/s/bdufstecru`). Карточки бюллетеней с датой и ссылкой.

### Загрузка .docx / .txt

1. Загрузите файл бюллетеня.
2. Система извлечёт BDU ID и связи с CVE.
3. Запустится **ИИ-анализ** сводки (если LLM настроен).

### Карточка BDU

- Описание на русском.
- Связанные CVE (ссылки в NVD-карточки).
- Экспорт **XLSX** риск-разбора (кнопка скачивания).

### БДУ за 24 часа

Отдельная панель для свежих записей БДУ в окне 24 часов — аналог hot board для отечественного реестра.

## 10. Patch Management (бюллетени вендоров)

Агрегатор **RSS/Atom** бюллетеней вендоров (Debian, Red Hat, Microsoft, ЦБ РФ и др.).

### Использование

1. Откройте модуль Patch.
2. Фильтруйте по вендору.
3. Откройте запись — ссылки на advisory и упоминания CVE.

Данные обновляются фоновым ingest (интервал настраивает администратор).

## 11. VOC (центр реагирования)

VOC — модуль для **оперативного реагирования**:

- **Кейсы** — инциденты/эскалации, привязка к CVE/BDU.
- **Смены** — передача контекста между сменами SOC.
- **Watchlist** — правила наблюдения (авто-попадание CVE в фильтры Threat).

### Создание кейса из Threat

В ленте Threat — кнопка **создать кейс**: подставляются CVE, threat score, причины.

## 12. Посты в Telegram из карточек

Из карточки **CVE** или **BDU** — кнопка **«Пост в ТГ»**:

1. Выберите статус: 🟡 В работе / 🔴 Срочно / 🟢 Устранено / ⚪ Не применимо.
2. Отредактируйте текст.
3. Отправьте.

Требуется настроенный Telegram-бот (см. раздел 7).

## 13. Экспорт XLSX

Из карточки CVE — **скачать XLSX**:
- сводный риск-разбор;
- источники;
- attack map данные.

Файл формируется на сервере; скачивание идёт с вашим JWT (не публичная ссылка).

## 14. Здоровье системы

Модуль **«Здоровье системы»** (иконка пульса внизу левой панели, над «Настройки») — единое место для всей технички и мониторинга.

### Вкладки

| Вкладка | Содержание |
|---------|------------|
| **Обзор** | Проверки API, BFF, CVE, vendors, ФСТЭК feed |
| **Очереди** | Глубина `ai.enrich`, `ai.score`, DLQ; пробы LLM / NVD / BDU |
| **DLQ** | Просмотр сообщений, повтор (retry), очистка — **только admin** |
| **Конвейеры** | Сверка NVD/EPSS/KEV/BDU: счётчики, lag, проблемы |
| **Управление** | Ops-кнопки (admin): EPSS sync, BDU sync, NVD hot-sync, hot24 rescore; Threat Intel refresh |

Вверху модуля — **readiness bar** (готовность источников к работе). Страница **`/health`** остаётся для прямой ссылки.

Если **LLM ok: false** — при `TEXT_ENGINE=llm` обогащение LLM недоступно; при `baseline`/`translate` карточки всё равно mature через фоновый BG enrich.

**Роли:** `viewer` — только просмотр; `analyst` — рабочие действия; `admin` — DLQ, digest prepare, TI refresh, ops sync.

## 15. Типовые сценарии

### Сценарий A: Утренний обзор (15 минут)

1. Открыть **Срочные 24ч** → просмотреть KEV/EPSS.
2. Открыть **Threat** → фильтр «только новые».
3. Для критичных CVE — создать **задачу** или VOC-кейс.
4. Проверить **Здоровье системы** если что-то «пустое».

### Сценарий B: Реакция на KEV

1. Найти CVE в KEV (hot board или поиск).
2. Открыть карточку → проверить затронутые продукты.
3. Создать задачу с вендором из CPE.
4. Пост в Telegram для команды.
5. Закрыть задачу с evidence после патча.

### Сценарий C: Бюллетень ФСТЭК

1. Модуль ФСТЭК → новый бюллетень в ленте.
2. Загрузить .docx при необходимости.
3. Пройти по BDU → связанные CVE.
4. Добавить CVE в задачу.

### Сценарий D: Суточный дайджест (админ)

1. Убедиться LLM health ok.
2. Threat → **Дайджест в Telegram**.
3. Дождаться прогресс-бара 100%.
4. Проверить канал: текст + PDF.

## 16. Частые вопросы

**Почему нет ИИ-текста в карточке?**  
LLM не настроен, CVE старше 24ч без ручного enrich, или очередь ещё обрабатывается.

**Почему 401 на всех запросах?**  
Сессия истекла — перелогиньтесь.

**Почему digest не отправился?**  
Prepare не завершился за 8 минут — дождитесь enrich или обратитесь к админу.

**Можно ли удалить CVE?**  
Нет через UI — каталог пополняется из NVD автоматически.

**Куда писать по багам?**  
Внутренний тикет / GitHub issues репозитория (по политике организации).
